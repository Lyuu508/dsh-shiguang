# B站返回 412 是什么意思

通常表示 B站拒绝了当前请求，可能是访问风控、网络出口或需要账号验证；只凭代码不能断定具体原因。它不是“已经看过视频”，也不等于二维码或 BV 号填写错误。

0.2.5 在后台显示真实失败环节，例如浏览会话准备、视频搜索、视频信息、视频流下载、评论发送或私信读取。HTTP 412 / 429 / 567，以及接口 -412 / -352 / 12015 会停止当前请求并进入持久冷却，默认 300 秒，可在 B站账号页调整；429 还会等待 Retry-After 要求的时间。普通业务接口不在冷却中反复请求，不轮换媒体地址绕过限制。

先在官方 B站 App 正常打开交给伙伴的账号，检查是否有验证或登录失效提示，按平台流程处理。插件仍允许主人主动检查账号和使用官方扫码。检查账号成功仅证明该检查通过，不能保证搜索或媒体 CDN 已恢复；冷却结束也不代表解除平台限制。

本次聊天没有创建延后补刷任务。受限的浏览只给当前失败事实，不声称“试了两次”或“等会自动去刷”；需要你之后主动再发起。原有自主生活会在它原本的调度时刻重新考虑，不会补跑这次聊天命令。

主人可以说“你去刷一些有趣的视频在评论区艾特我去看”，不必强制写 B站。明确本次推荐不依赖“自主推荐”开关，但必须打开账号评论权限、填写主人 UID 白名单，并实际识别到内容。只有评论 ID 回执才说已推荐；没有权限 / 额度 / 回执时明确未完成，不拿标题当观看结果。自动浏览时是否自行推荐，继续由原来的自动推荐开关控制。

## 0.2.6：先排除视频信息遗漏登录会话

发现并修复了视频信息 / 分 P 元信息未携带已保存会话的问题：同一客户端的搜索、标签已经带登录，但 view 请求仍是访客，可能让“账号检查正常”和“视频信息 412”同时出现。现在沿用当前身份会话，并取消同一个分 P 的重复元信息请求。这是代码侧缺陷，不证明每次 412 都由它造成。

升级到 0.2.6、重启 DSH 并刷新后，先暂停自主生活，检查插件里的伙伴登录状态，失效时在插件里重新扫码。在同一台电脑浏览器登录伙伴号正常打开待看视频，按实际提示处理官方验证；浏览器登录不会自动替换插件凭据。保留默认 300 秒冷却，待冷却结束先手动测试一个普通公开视频，成功后再恢复自主浏览。反复点击和把冷却设为 0 不会解除平台限制。

若正确携带会话仍返回 412，插件继续停止；账号、网络出口或平台验证需在本机确认，不能承诺等五分钟一定恢复。无需在聊天中提供 Cookie。
