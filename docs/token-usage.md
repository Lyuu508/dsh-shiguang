# 完整 Token、统计范围与账单

0.2.1 以前只把已拆出的未缓存输入、缓存读取 / 写入和输出相加，没有保存服务的 `totalTokens`。当适配器给出了完整总量、却未拆全缓存等字段时，会少算。另一项差异是旧表只包含拾光自己的请求，服务商“全部 Key”的账单还可能有 DSH 主聊天、其他插件、软件或设备。仅靠截图不能确定每一笔差额来自哪里。

## 两个统计范围

- **拾光当前角色**：QQ、媒体、主动、B 站与 `shiguang_chat` 的模型尝试，按本角色分类。
- **整个本机 DSH**：本版加载后经过当前 DSH 实例的模型请求，包含主聊天、其他插件及其他角色。独立读取请求流水，不和角色表再次相加。只保存计数、时间、会话标识和模型，不保存其他聊天原文、工具参数或密钥。

插件关闭、其他程序 / 设备、未返回回执的用量不在完整观察范围。页面显示观察开始时间与未完成请求，和服务商对账需统一日期、时区、模型与账户 / Key 范围。不同提供方可在“按模型查看”区分。

## 总量与明细

优先保存服务返回的完整 `totalTokens`。没有完整总量时，只有输入 / 输出与所有缓存桶均有明确值才按完整分项求和；旧记录、缺少缓存桶或缺失 usage 均标记总量不完整，不把未知当零。

“未细分”是完整总量中尚未落入细分字段的部分，不冒充未缓存输入。完整总量与明细矛盾时明确提示，保留可核对的原始计数。推理通常属于输出的一部分，不再额外相加；同一次尝试的累计 usage 取最后值，工具步骤、重试和失败的不同尝试各记一次。

“已记录总量”可能含只有部分数据的请求；“完整回执合计”只算总量完整的请求。缺失数据时两者都不能冒充全账户最终账单。分段发送、概率、计时、扫码、本地记忆查询本身没有模型用量。

## 补齐旧数据

选择日期，展开“补齐旧会话用量”，点“从 DSH 日志补齐旧用量”。只读取已经登记过的拾光会话的持久化日志，提取 usage，不调用模型或重跑对话；如果原始流仍有完整总量，可补回旧版忽略的值。重复操作不增加调用次数。

没有持久化服务、旧文件缺失、未落盘的一次性视频请求或服务本来就没返回 usage 时无法补造。不会为了凑到账单金额乘系数，也不扫描所有私人聊天去猜 Token。

## 实际金额与对账

展开“核对服务商的实际账单”，填控制台里的总 Token、请求数（可选）和实际金额。该记录明确标为**手动账单核对**，金额不是插件估价，也不是插件自动取得的扣款。整个 DSH 视图显示账单与本机记录的差额，帮助核查范围和缺失；差额本身不能证明某一种漏记原因。

先做一天小规模对照：记录开始值，发几轮普通 QQ 碎句，确认一轮只生成一次；再做历史追问、视频和自主任务，逐组刷新。最后导出当日记录，与同日同 Key 范围的服务商账单核对。模型每次都会计算实际携带的上下文，输出上限不是整次请求的 Token 上限。

## 评论 @、同兴趣热评与推荐的用量

通知 / 私信轮询、播放量排序和本地 GIF 差异去重不调用模型。新主人评论 @ 的回复与工具步骤归为“B站评论 @ 任务”；私信任务按原有 B站分类记账，不与整个 DSH 流水重复相加。同兴趣热评放进已有自主思考，总正文预算默认 1000 字符；聊天发起的浏览仅在推荐权限和额度满足、有成功读取内容时增加一次有限推荐判断。

动图默认最多 8 张画面，动作过程模式可按预算分图，全部图片在同一次视觉调用中发送；不为每帧额外请求模型。图片 Token 的实际计费仍以服务完整 usage 回执为准。

## 图片识别自检

QQ 页“测试模型能否看图”只发送内置简单图片，不读 QQ 或个人记忆、不调用 FFmpeg；每次点击产生一次模型请求，成功和失败返回的实际 usage 都单列为“图片识别自检”。它与 QQ 媒体分类分开，整个 DSH 观察视图仍只计一次。图片、输出和附件请求的具体计量以服务回执为准。

0.2.7 对 QQ 媒体、B站关键帧与表情收藏的短识图调用显式关闭思考，避免默认思考占掉短输出预算；这不是整次输入 Token 上限，图像仍有服务计费。

内置解码引擎检测、旧工具清理、时间读取及动画筛选均不调用模型。当前时间与作息作为有限文字放入已有请求，不额外调用一次模型；动图动作模式可发送少量有序分图，按真实服务回执计量。


群友明确解释黑话时本地写词库，不触发模型；在自主接话中积累词义时复用该次判断 / 回复调用，沉默也有那次调用的实际用量。表情含义复用识图或收藏挑选调用，发送匹配和手工纠正不调用模型。结构化标签和动作分图可能改变输入 / 输出用量，不承诺固定节省比例。
