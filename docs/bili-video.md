# B 站视频内部内容

在 **B 站账号** 登录伙伴账号，开启 B 站工具与视频内容识别并保存。使用 DSH 最新 Flash；本机解码由插件的内置引擎负责，无需外部 FFmpeg / FFprobe 或程序路径。

## 使用

在主人 QQ / B 站私信中说 `看看这个视频里的内容：BV……`，或在 B 站页手动填写完整链接 / BV 号、分 P 和问题后测试。手动指定默认不要求命中自动浏览白名单，黑名单仍优先；开启严格白名单后需同时满足。

1. 读取有权限的视频元信息、分 P CID 与时长，沿用当前伙伴的登录会话。
2. 从 B 站返回的官方媒体地址下载，核对大小和时长；返回网页 / 错误文本时停止。
3. 内置视频引擎取候选画面，按差异筛选。浅看默认最多 4 帧、768 像素拼图。
4. 有可用平台字幕时按时间节选，默认最多 1800 字符。画面和字幕在一次视觉调用中返回短结果，默认输出 480 Token，关闭思考。
5. 客观摘要保存到共享记忆，默认 24 小时复用；命中不再下载媒体或发视觉调用，仍核对身份、标签和权限。

## 600 秒是什么意思，在哪里改

在 **B站账号 → 看 B站视频里的内容 → B站单个分P时长上限（秒）**直接填写并保存，默认 600 秒，即 10 分钟。它限制整个分P的时长；“深看每段秒数”只控制分段长度，调大分段数不会替代总时长上限。较长攻略可按实际长度设置，例如 1800 秒；下载、处理等待及分段 / 每日额度也需足够。

超过时长时会在播放请求前停止这个视频，显示实际秒数、当时保存的上限和设置位置，提供“调整B站时长上限”跳转按钮。改完需保存并重新发起浏览，历史失败保留原上限，同时显示当前值。停止一轮后，未完成和未开始的视频会标清，不再停留“正在读取”。

B站“画面筛选方式”也可选择差异或均匀，两者仍受每段帧数与像素预算约束。较小原图不强制放大。

## 浅看与分段深看

浅看覆盖整段的少量候选，不保证每个情节被选中。深看默认按 90 秒分段、最多 8 段，每段独立选择画面并调用一次视觉模型；使用原时间范围，临时文件不依赖中间转码。

例如 6 分钟分 4 段，需要 4 次视觉调用。只有全部段完成才写完整摘要和覆盖范围；中途失败不缓存完整结论，已返回 usage 仍记录。分段也属于抽样，不能声称逐秒、逐帧看完或听完原声。提高段数会增加费用。

默认不在自主浏览时识别画面。需要时开启 **自主浏览时也识别视频内容**；权限、每轮视频上限、刷满选项、总时长与每日识别额度仍生效。识别每日默认上限 12 次，深看按段计次。元信息、模型选择和实际识别 / 缓存 / 失败数分别显示。

## 安装与迁移

0.2.8 的解码核心随插件依赖安装；首次升级请等 DSH 完成安装。**内置动图与视频引擎 → 检测** 只做本机检测，不调用模型。

升级检测成功后，自动清理拾光旧安装记录对应的便携 FFmpeg、FFprobe、ZIP 和断点；不使用旧路径，不卸载手动或系统安装。无有效归属记录、链接或删除失败时保留文件。旧版“安装 / 修复”“自动定位视频工具”和路径输入已移除。[QQ 与引擎排查](qq-media.md)

## 错误应在哪一层处理

- HTTP 412 / 429 / 567、登录过期或播放权限：平台读取失败，停止并按限制冷却；在官方客户端处理实际验证。引擎能启动不代表平台已经解除限制。[平台限制](bili-risk.md)
- 检测流 / 候选画面 / 提取画面 / 拼图失败：本机内置解码阶段；查看展开诊断、实际格式和处理预算。不会再因用户本机旧 FFmpeg 参数不兼容而调用失败。
- 视觉模型未完整返回：图片模型阶段；检查 QQ 页“测试模型能否看图”和结束原因。不会为了改格式自动增加一次付费重试。

网络和平台失败不会冒充媒体解码失败；没有真实画面结果时不把标题和简介当作已观看。内置核心仍使用 FFmpeg 编解码库，支持的常见封装 / 编码已本机验证，特殊编码、损坏媒体和真实账号效果仍需现场核对。[依赖说明](third-party.md)

## 用量与数据

下载、字幕读取、内置解码、检测和清理不消耗模型 Token。视觉请求归为 **B 站视频识别**，主人任务回复与自主思考分别计量，不与整个 DSH 流水重复相加。图片、字幕和回答以服务的完整 usage 为准，输出预算不是整次输入上限。

仅请求固定 B 站接口与官方 HTTPS 媒体域名；账号 Cookie 不交给视频 CDN 或模型。临时文件处理后清理；摘要与具体视频链接按角色保存。主人兴趣账号与伙伴会话独立，不为绕过平台限制切换身份。
